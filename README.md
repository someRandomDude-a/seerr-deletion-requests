# Deletion queue Jellyfin repositories

The `manifests` branch is generated by the tag-release workflow. Do not register the GitHub HTML page or a runtime ZIP as a Jellyfin repository URL.

Choose **one** architecture and channel. URLs become available after the first successful release:

| Platform | Stable | Preview (includes stable releases) |
| --- | --- | --- |
| Linux x64 / standard Jellyfin Docker on AMD64 | `stable/manifest-linux-x64.json` | `preview/manifest-linux-x64.json` |
| Linux ARM64 / standard Jellyfin Docker on ARM64 | `stable/manifest-linux-arm64.json` | `preview/manifest-linux-arm64.json` |
| Windows x64 | `stable/manifest-win-x64.json` | `preview/manifest-win-x64.json` |

Prefix each path with `https://raw.githubusercontent.com/someRandomDude-a/seerr-deletion-requests/manifests/`.

Jellyfin 12.2's repository format has no architecture or prerelease selector: do **not** register multiple runtime catalogs or both channels. A manifest's `targetAbi` is a minimum server ABI, not an architecture selector or an upper compatibility bound. These builds target Jellyfin 12.2 / .NET 10; other server/client releases still need certification.

The current release is a **safety preview**. Stable catalogs intentionally contain no current version until a release is explicitly marked stable in `build/Plugin.props`. No release changes the plugin's automatic-deletion safety gates or migrates/reset its retained authorization state.

Every version entry retains an immutable tag-specific download URL, Jellyfin's required MD5 checksum, ABI, changelog and UTC commit timestamp. Releases also supply SHA-256 checksum sidecars and GitHub build provenance. MD5 is for Jellyfin compatibility, not cryptographic authenticity; use trusted HTTPS URLs, GitHub attestations and SHA-256 for additional verification.

See the source repository's `docs/releases.md` for publishing, recovery and platform limitations.
