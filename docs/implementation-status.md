# Implementation status — integrated Web and Seerr-managed removal

This .NET 10 / Jellyfin 12.2 plugin now has an integrated Web UI and a registered stock-Seerr execution gateway. **The explicitly accepted trust boundary changed:** Seerr controls Arr targeting/file removal and its DELETED result is trusted. Local authenticated journal/seals are used without an independent backup-rollback witness. Current consent, continuous activity coverage, bounded related-item/all-account scans, delay and one-shot durable claims remain required. An old preview-only opt-in does not enable the new transport.

## Operational limits and compatibility boundary

1. **Seerr trust, not atomic pinning:** the legacy stored `FilesPinned` field remains false; it is no longer an execution gate. Seerr 3.5.0 resolves service and movie/series at dispatch time and supports no atomic file-set precondition. Preflight mapping checks cannot eliminate that race. Its successful deletion/status report is accepted rather than independently certifying physical file absence.
2. **No independent rollback witness:** local seals reject tampering, omissions and mismatched partial restores, not replay of a complete consistent old database/key/seal set. Never restore old claims to retry deletion. This limitation was explicitly accepted, not solved or hidden.
3. **Inventory budgets:** scans are bounded to 500 accounts, 200 aliases, 20,000 children per series alias, 100,000 account/item pairs, 1,024 sessions and a three-second inner scan budget. Exceeding a bound blocks eligibility. Continuous observation (default 14 days after every restart) is still required for historical non-playback interactions. No direct Jellyfin database access is used.
4. **Series authority:** mixed approved ownership or incomplete/missing Seerr-managed season evidence blocks Own requests. Wider authority does not bypass activity, consent or delay.
5. **Web clients only:** native TV/Roku/Swiftfin clients are not injected. Controls target stock Web's media/detail/native action-sheet contracts and the Enhanced Requests DOM contract at `e46b1129d68bd56505dcbfbb31f5478ffa6ef7c9`; unsupported markup omits controls. Enhanced requests without native media IDs show removal unavailable rather than guessing IDs from titles.
6. **Notifications:** owners and recent/playing required viewers are notified automatically, with personal opt-out; optional extra subscriptions remain supported. No external push delivery. Polling/opening does not mark notices read or approve deletion.
7. **Migrations/key rotation:** current schema reopens without altering valid keys/seals/settings. Unknown versions are rejected; no legacy import, forward migration or key-rotation tooling is shipped yet. Historical data is never fabricated or resealed.
8. **Performance/operations:** authenticated snapshots are replay-validated on every access. Capacity/replay limits stop the plugin rather than exhaust host resources; no automatic compaction/archival migration exists. This is not production-scale storage optimization. Stale session IDs are cleared only after a complete live-session scan and invalidate consent; clock discontinuities remain fail-closed.

## Test boundaries

The domain/storage/transport suite uses simulated gateways and HTTP handlers. The Docker Web fixture mounts no media and uses no production credentials. Enhanced/media/proposal browser contracts use synthetic DOM/API responses, not a live Seerr/Arr stack. These tests do **not** certify real Sonarr/Radarr file removal or arbitrary third-party themes/Enhanced versions.

The standalone page/redirect, UI/theme assets, lazy stylesheet scanner/service and its obsolete test are removed; the integrated API remains. API smoke checks explicitly require 404 for retired routes/resources and reject ordinary-user admin approval attempts. Persisted compatibility fields and authenticated history are retained rather than silently reset.

The latest stable Server and Web release APIs both report **v12.2**. The isolated pinned Docker fixture passes API/hostile-input checks and Chromium tests for injection, real Web login/navigation, global/mobile bell, text-only notices, explicit reads/consent/Undo, synthetic media/Enhanced/action-sheet contracts, custom CSS, Escape/session clearing, native user dropdown/reset and real-deletion confirmation/cancellation. Corrupt-head-seal fault injection again confirms Jellyfin health/user APIs survive worker failure and restart without repairing the seal. This does not substitute for a live Enhanced+Seerr+Arr media-deletion acceptance test.

Remaining integration and release gates in the implementation plan still apply. Do not interpret a green unit-test run as independent security review, full restore certification or permission to turn on an unsafe transport.
